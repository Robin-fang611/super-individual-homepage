# 个人主页设计文档

日期：2026-06-09

## 设计目标

这个网站是 Robin 的个人 3D 世界入口，不是传统简历，也不是普通博客。

核心概念是“进化者的星辰大世界”：访客进入后，不是看一张网页，而是进入一个可探索的深空场景。Robin 的经历、项目、文章、能力变化和阶段复盘，都以展开后的星路、水墨星河、星光信标和星座节点呈现。

第一版目标直接升级为纯 3D 沉浸体验：先做出类似大世界游戏入口的空间感、镜头感、探索感和节点点击体验。文章详情页、完整项目页、简历页和联系方式仍放到后续阶段。部署方向保持 Cloudflare Pages。

已选定第一版视觉方向：`展开后的深空水墨星路`。现有星路素材是视觉母版，所有新增内容都必须顺着原图的星云、星尘和能量流生长，不做建筑、观测台、浮岛或割裂的新地标。

## 不做什么

- 不强调“创业者”身份。
- 不做传统简历模板。
- 不做普通博客列表页。
- 不做游戏宣传页。
- 不做完整 RPG 游戏系统：不做角色养成、战斗、任务、背包、数值、登录和存档。
- 不直接使用《斗破苍穹》《吞噬星空》《完美世界》等版权素材。
- 不照抄具体角色、法阵、武器、宗门、怪物、地图或 IP 设定。
- 不做登录、评论、后台、数据库。
- 不在第一版做文章页、项目页、简历页或联系方式。

## 核心体验

网站本质仍按时间和成长阶段组织，但视觉表达从“星路时间线”升级为“可进入的 3D 星辰世界”。

访客从当前星路的近景端出发，通过镜头飞行、拖拽环视或点击信标，探索远处的历史节点。越靠近近景星路，越接近当前状态；越往远处星河探索，越接近过去的关键经历。未来内容可以继续接在当前端，让这条星路持续扩张。

每一个信息节点不再只是平面星点，而是星路中的可交互光标。节点表现为星光密度、轨道微环、粒子聚合和水墨晕染的变化，用来承载项目、文章、能力变化、里程碑或当前状态。第一版先建立当前近景节点、过去节点和基础探索路径。

## UIUX 决策

### 视觉强度

采用“克制玄幻 + 大世界游戏入口”。

视觉参考接近国漫玄幻星空和开放世界游戏登录场景中的深空、能量流、远景地标、巨大尺度和仪式感，但压低战斗感。页面要让访客第一眼感到“这里是 Robin 的世界”，同时保留个人主页的信息可读性。

主色采用深蓝黑、银白星光、冰蓝能量和少量暖金高光。背景可以有星云、远处天体、空间尘埃、能量雾和流动轨道，但不能被大面积紫黑、金色或复杂纹样淹没。

标题区使用现代高识别度字体为主，行楷气质可作为少量点缀，不再把整体做成古风模板。正文、导航、面板仍使用现代无衬线字体，保证信息清楚。

### 空间结构

采用“展开星路 + 可飞行星河 + 远方节点群”的纯 3D 结构。

首页第一屏不改原有构图：左侧暗场仍给 `Robin` 和副标题，右侧星云漩涡和星路仍是画面主角。展开后的星路从原有光河自然延伸，近景当前节点通过星光密度和水墨雾化增强，不额外放置建筑或硬质地标。

新增视觉只能作为原图气流的一部分存在：星光颗粒更密、水墨边缘更柔、光路层次更深。任何看起来像“贴上去”的几何体、平台、塔、浮岛或 UI 标记都不进入第一版。

星路不再是轻微弧线或 2.5D 轨道，而是一条真实存在于 3D 空间里的能量航道。它可以上下起伏、穿过星云、绕过远景天体，并连接不同年份节点。时间方向仍然清楚：当前在近处，历史在远处或深处。

镜头不是平面拖拽，而是 3D 相机控制。桌面端默认使用自动缓慢环绕，让世界先“活起来”；用户交互后进入手动探索，可以拖拽环视、滚轮推进/拉远、点击节点飞行聚焦。镜头需要被限制在合理范围内，避免用户飞出世界或看到空白背面。

### 3D 地标设计

采用“可感知星标”，不做建筑地标。

当前节点应该是星路中最强的光学锚点，可以通过粒子聚合、柔性光晕、轨道微环和局部水墨亮边来表达。历史节点降低亮度和尺寸，像被星路照亮的远方信标，而不是独立模型。

第一版当前主节点固定为“近景星光聚合点”：星光密度提供识别度，水墨雾化提供高级感，微弱轨道线提供可点击暗示。后续重要项目节点也优先保持星路语言，不升级为建筑或浮岛。

节点层级分为三类：

- 当前主节点：代表现在的 Robin，是进入星路的起点。
- 关键历史节点：代表重要经历、项目或转折，有轻量星标和弱标签。
- 背景星群：只承担氛围和纵深，不可点击或弱交互。

默认状态下不在场景里堆大量文字。年份和标题使用 3D billboard 标签或屏幕空间标签，只在节点靠近、hover、聚焦时增强显示。hover 时节点发光、轨道亮起、镜头轻微吸附，暗示可点击。

### 信息展开

点击节点后，镜头先短距离飞行到该地标附近，再打开信息面板。

桌面端使用右侧信息面板，但面板不能破坏沉浸感。它应该像游戏里的轻量信息 HUD：深色半透明、冰蓝细边、短内容、少装饰。第一版面板只承载标题、年份或日期、一句话摘要和节点类型。

手机端仍使用底部抽屉，但 3D 场景不能降级为普通列表。点击节点后，镜头聚焦节点，底部抽屉显示摘要。抽屉高度要克制，避免遮住整个世界。

### 导航方式

采用“游戏式探索 + 快速定位”的导航。

页面常态保留沉浸式 3D 世界。导航通过小星盘按钮、节点索引和快捷聚焦完成：

- 桌面端：拖拽环视，滚轮推进/拉远，点击节点聚焦；小星盘打开快速导航。
- 键盘增强：可选支持 `WASD` 或方向键轻量移动镜头，`Q/E` 拉近拉远。
- 手机端：单指拖拽环视，双指缩放或按钮切换节点，点击节点聚焦。

导航不是传统网站菜单的主角，而是“星图”。第一版至少保留“回到星路入口”“当前节点”“历史节点”三个快速入口。

### 首页第一屏

首页第一眼就是 3D 世界。

初始画面要看到 Robin、原有星路和远方可探索节点，而不是先看到大段文字。`Robin` 作为品牌标题悬浮在左侧暗场安全区，不能挡住右侧星路主视觉。副标题“星辰，进化之路”可以保留为短句。

第一屏构图继续采用当前网站的“左侧文字、右侧星路”平衡方式，但不做传统左右分栏。文字像 HUD 一样悬浮在深色安全区，右侧星云与光河占据视觉中心，远方节点从原星路深处浮现。

进入探索后，标题不常驻遮挡场景。它可以淡出、缩小为角落标识，或化为星尘。核心目标是让 3D 世界本身承担第一印象。

### 手机端

手机端仍保留纯 3D，但降低自由度。

手机不改成纵向滑动星轨，而是使用受控 3D 探索：默认自动环绕，用户单指拖拽改变视角，点击节点聚焦，必要时用“上一个/下一个”切换节点。性能上要降低粒子数量、后处理强度和远景细节，但不能把体验退回 2D。

## 信息架构

第一版只包含 3D 世界入口与节点探索骨架：

- 当前星路入口：现在的 Robin 正在做什么。
- 时间航道：按年份连接经历和内容节点。
- 节点摘要：点击地标后显示短信息。

以下内容层作为后续阶段加入：

- 项目：可证明能力和实践结果的作品。
- 文章：观点、复盘、学习记录。
- 简历摘要：可快速理解经历和能力的入口。
- 联系方式：低打扰的联系入口。
- 世界地图：当节点变多后，用星图方式快速跳转。

## 节点类型

每个节点至少包含以下字段：

- 标题
- 日期
- 年份
- 类型
- 摘要
- 可见状态
- 是否当前节点

建议保留以下节点类型设计：

- `now`：当前状态
- `milestone`：关键节点
- `project`：项目或作品
- `article`：文章或复盘
- `skill`：能力变化

第一版可以继续只实现 `now` 和少量 `milestone`，但视觉上要把它们渲染为 3D 地标，而不是 2D 星点。

## 内容维护

维护频率按每月整理一次设计。

内容维护方式继续采用 Markdown + frontmatter。每个节点可以是一份 Markdown 文件，frontmatter 写日期、年份、类型、标题、摘要等元信息，正文写具体内容。

第一版采用最小节点字段：

```markdown
---
title: "开始搭建个人星辰大世界"
date: "2026-06-09"
year: 2026
type: "now"
summary: "建立一个以 3D 星辰世界为核心的个人主页。"
visibility: "public"
current: true
---
```

字段说明：

- `title`：节点标题。
- `date`：具体日期，用于排序。
- `year`：年份，用于形成时间航道和年份节点群。
- `type`：节点类型，例如 `now`、`milestone`、`article`、`project`、`skill`。
- `summary`：一句话摘要，点击节点后显示在信息面板。
- `visibility`：公开状态，第一版先使用 `public`，后续可扩展 `draft`。
- `current`：是否为当前主节点，第一版只需要一个当前主节点。

第一版暂不加入后台编辑、复杂标签系统、封面图和长正文展示。节点空间位置可以先由日期自动排布，但 3D 渲染层要把自动位置转成可探索的地标布局。后续如果要精细布置世界，再考虑给节点增加手动坐标字段。

每月维护时，只需要新增或整理少量节点，不要求高频更新。网站不应依赖日更或周更来显得活跃。

推荐每月维护动作：

- 更新当前状态。
- 新增本月重要项目、文章或复盘。
- 检查旧节点是否需要补充链接。
- 隐藏不再适合公开展示的内容。

## 技术边界

第一版按静态站处理，优先适配 Cloudflare Pages。

3D 实现以 Three.js/WebGL 为核心。项目可以继续保持无构建或轻构建路线，优先复用当前本地 `three.module.js`，不因为视觉升级就默认新增依赖。

技术实现不应在第一版引入登录、数据库、复杂后台、评论系统、物理引擎、角色控制器或大型游戏框架。内容可以先由本地结构化文件维护，再由页面读取渲染。

必须控制性能风险：

- 桌面端优先保证 60fps 体感，粒子、透明材质和发光效果要克制。
- 手机端降低粒子数量、材质复杂度和相机自由度。
- 提供 WebGL 失败或低性能设备的基本降级提示。
- 不使用过大的贴图、未压缩视频或版权不清的素材。

## 视觉素材原则

可以借鉴国漫玄幻星空和开放世界游戏入口的气质，但不能直接使用版权图，也不能照抄具体角色、法阵、武器、宗门、怪物、地图或 IP 设定。

正式设计应提炼为更通用的视觉语言：

- 深蓝黑宇宙
- 巨大远景天体
- 展开后的深空星路
- 水墨雾化光河
- 银白星光
- 冰蓝能量粒子
- 三维星路航道
- 微弱星云和空间尘埃
- 可点击地标节点
- 克制的暖金高光

## 下一步

下一步进入 3D 重设计实现计划，不再按 2.5D 星路继续细化。

建议优先确认并实现：

1. 定展开后星路的核心形态：原图光河延展、星光颗粒、水墨雾边、近景当前节点。
2. 定 3D 星路航道：近处当前节点、远方历史节点、年份节点群。
3. 定镜头控制：自动环绕、拖拽环视、滚轮推进、点击飞行聚焦。
4. 定节点地标样式：当前主节点、关键历史节点、背景星群。
5. 定性能边界：桌面完整效果，手机受控 3D 简化。
6. 基于现有 Three.js 代码重构 3D 场景。
