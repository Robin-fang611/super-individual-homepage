# Robin 个人宇宙地图 · 产品与架构文档

> 一句话：一个可以"飞"的个人主页。访客进入一个墨色宇宙，你的个人记录是一颗颗被星光照亮的星标，飞近、点亮、点击，就能读到你写下的内容。

---

## 1. 产品是什么

### 1.1 产品定位

- **形式**：个人主页（纯静态站点，无需服务器）
- **体验**：第一人称 3D 自由飞行。不是滚动的网页，是一个可探索的空间
- **表达**："个人宇宙地图"——每一条记录（文章、想法、里程碑）是一颗星，按时间排成一条星路，从"起源"飞向"当前"
- **受众**：访问 Robin 主页的人。无需注册、无游戏操作门槛，进入即可沉浸

### 1.2 核心体验流程

```
进入页面 → 黑场字幕「这里是，我的世界」→ 自动入场飞行（约4.3秒）
→ 控制权移交玩家 → 自由探索星路 → 点击星标 → 阅读记录 → 关闭继续飞
```

三个关键阶段（运行时状态机）：

| 阶段 | 体验 | 时长 |
|------|------|------|
| intro 入场 | 自动飞行，镜头缓缓穿过星路，字幕渐隐 | 4.3s，任意操作可提前接管 |
| handoff 移交 | 控制权从"自动"平滑过渡到"玩家"，防止手感突变 | 0.4s |
| active 自由飞行 | 完全由玩家控制；靠近边界减速但不阻挡环视 | 持续 |

### 1.3 操作方式

| 输入 | 动作 |
|------|------|
| 触控板横向/纵向 | 第一人称环视 |
| 触控板捏合 / Ctrl+滚轮 | 向前/向后飞行 |
| WASD / Space / E / Shift / Q | 平移与升降 |
| 点击星标 | 跳近并打开阅读面板 |
| 右上角指南针按钮 | 快捷跳转：星路入口 / 当前 / 远处节点 |

### 1.4 视觉语言（设计约束）

- **风格**：深空水墨星路——星光颗粒 + 水墨晕染 + 能量流，克制、沉静、可探索
- **主色**：冰蓝为主光，暖金仅做少量历史节点高光；禁止高饱和紫、荧光青、大面积金
- **禁止项**：建筑、浮岛、平台、强光晕、赛博线框、游戏 UI 感
- **低保真原则**：星标是"被星光照亮的点"，不是按钮、不是卡片

## 3. 关键机制详解

### 3.1 星路布局（一条有意义的路径）

`star-layout.mjs` 把记录按时间排成空间中的一条曲线路径：

- 按"当前在前、其余按日期倒序"排序
- 每条记录在路径上获得一个 3D 位置（沿弧线推进，带横向摆动与纵向起伏）
- 这条路径就是"进化之路"——从过去的节点飞向"当前"那颗核心星
- 布局是纯计算（确定性），同一条数据每次访问生成的宇宙完全相同

### 3.2 星标（内容节点的可视形态）

`content-beacons.mjs` 把每条记录渲染成一颗"信标"，分三个层级：

| 层级 | 规则 | 视觉 | 交互 |
|------|------|------|------|
| core 核心 | `current: true` 的记录 | 金辉光核 + 椭圆轨道环 + 常显年份标签 | 命中半径最大 |
| key 关键 | 里程碑类型或重要度 > 0.6 | 银色光核 + 光环 + 悬停才显标签 | 中 |
| field 普通 | 其余 | 青墨光点，无环 | 小 |

- **点击检测**：把星标世界坐标投影到屏幕，与指针距离小于命中半径即命中（取最近）
- **悬停反馈**：光核放大、透明度提升、标签浮现；飞行中自动弱化标签降低视觉噪音

### 3.3 飞行物理（边界是软的）

`flight-model.mjs` 是纯数学模块（不依赖 Three.js）：

- 输入 → 方向向量 → 目标速度 → 平滑加速度趋近（`1 - e^(-rate·dt)` 响应曲线）
- 世界是一个半径 24 的球体（飞行边界），全景背景壳在 25.2 处
- **软边界**：接近边界时只减弱"向外"的速度分量，保留沿边界滑行与自由环视——不会撞墙，也不会飞出宇宙
- 固定 120Hz 步长 + 多子步插值，保证任何刷新率下飞行手感一致

### 3.4 画质自适应（同一世界，四档观感）

```
设备能力评估(WebGL2/内存/线程) ──▶ 初始档位
        │                              │
        ▼                              ▼
  帧耗时监控(滑动120帧) ◀──▶ 长帧超标 ──▶ 逐级降档（自动）
        │
        ▼
  手动选择 ──▶ 写入 localStorage，始终优先
```

- 四档共用同一世界种子（611），**降档不改变宇宙的空间结构**，只换背景图分辨率、减少墨云数量和星屑密度
- 用户手动设置永久生效；纯自动模式只降不升，避免画质抖动

### 3.5 容错与降级（三条防线）

1. **WebGL 不可用 / 场景启动失败** → 显示"墨色暂时无法成形"降级层
2. **WebGL 上下文丢失** → 暂停场景并报告降级
3. **无 JavaScript** → noscript 静态提示

### 3.6 安全

- 所有用户内容（Markdown）经 `escapeHtml` 转义后渲染，无 XSS 风险
- 内容 frontmatter 校验：必填字段、日期合法性、重要度范围钳制

## 4. 内容运营（如何添加新记录）

### 4.1 数据结构

```
content/records/
├── index.json          # 记录清单（文件名数组）
└── 2026-06-15-xxx.md   # 每条记录一个 Markdown 文件
```

### 4.2 单条记录格式

```markdown
---
title: 记录标题
date: 2026-06-15
type: 里程碑          # 可选；type: 里程碑 会升级为 key 级星标
summary: 一句话摘要
importance: 0.8       # 可选，0~1，影响星标大小与光晕
visibility: public    # public 才会显示；draft 隐藏
current: true         # 可选；标记"当前"，成为核心星
---

正文内容，支持 # ## ### 标题与段落。
```

### 4.3 更新流程

1. 新建/编辑 `content/records/` 下的文件，并把文件名加入 `index.json`
2. 运行验证：`node scripts/validate-content.mjs`
3. 部署到 Cloudflare Pages（自动生效）

| 真实内容 | ⚠️ 目前是 3 条测试记录 |

### 6.2 已知遗留（后续可清理）

1. **双内容管线未合并**：`src/star-content.mjs` 是与 record-content 平行的一套 stars 管线，当前主流程未使用。建议二选一，避免两套解析逻辑漂移
2. **编排层访问私有 API**：`app.mjs` 通过 `starField._inkWorld` / `starField._onSelect` 触达内部对象，且用 400ms 轮询感知入场移交。建议为 starField 补充公开接口（如 `navigateTo(starId)`、事件回调），消除隐性耦合
3. **移交互感**：指南针跳转目前是"瞬移"，未来可做飞行过渡动画

### 6.3 建议的演进方向（按价值排序）

1. **填充真实内容**：3 条测试记录换成真实经历，产品立即可用
2. **移动端适配决策**：当前明确不做触屏操作，是否保留此边界需要产品判断
3. **星标详情富化**：阅读面板目前只支持标题+正文，可扩展图片、链接
4. **分享能力**：可分享单条记录链接（如 `#star-2026-06-15`）

## 7. 一句话总结

> 技术上是"纯静态页面 + Three.js 3D 场景 + Markdown 内容管线"，三个世界用一套编排串起来：**数据世界**（内容解析）→ **空间世界**（飞行与星标）→ **阅读世界**（记录阅读）。产品上它把个人主页从"被浏览的页面"变成了"被探索的宇宙"。
