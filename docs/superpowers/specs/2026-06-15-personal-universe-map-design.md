# Robin 个人宇宙地图设计文档

日期：2026-06-15

## 结论

新版个人站不是传统首页、简历页、博客页，也不是游戏。它是一张可漂移的个人宇宙地图，用完整星空承载 Robin 的个人记录、思考感悟、价值观和项目经历。

首版目标是确定前端体验骨架：黑场开场、纯星空探索、视差漂移、少量可发现记录节点、星空背景阅读模式。内容可以先用测试占位，真实记录后续再逐步替换。

## 核心体验

用户进入页面后，先看到纯黑背景和开场文案：

```text
这里是，我的世界
                               ——Robin
```

随后文字和黑场向中心收缩成一点，星空亮起。开场结束后进入探索态。

探索态是完整星空，没有文字、年份、标签、导航和明显按钮。用户通过鼠标或触控板上下左右拖动，在巨大星海中漂移。拖动不是平面图片移动，而是多层宇宙视差：远景星云慢，中景星河正常，近景星尘快，形成类似 3D 的空间手感。

记录节点按时间自然分布在星河中。越近越新，越远越早，但探索态不显示年份或日期。背景星点很多，可点记录节点很少。用户靠亮度、呼吸、靠近反馈和拖动时短暂显影来发现节点。

点击节点后，星空背景保留但变暗、变慢或轻微失焦，进入阅读模式。关闭阅读后，页面回到纯星空探索态。

## 视觉方向

整体画风是深空宇宙、强星云、水墨气流、轻粒子、光河和少量星尘高光。不要做普通黑底星点，也不要做赛博网格、硬质科幻仪表盘、按钮化星图或传统网页 hero。

视觉分两层：

1. 完整宇宙氛围。开放给用户拖动到的区域必须有星点、星云、光流或水墨气流，不能出现大面积空白黑场。
2. 主星河与记录节点。主星河是时间轨迹，也是“命定之路”的隐喻。它可以弯曲、回旋、浓淡变化，但不能变成清晰时间线 UI。

视觉原则：宇宙先成立，节点后出现；气氛先成立，信息后出现。

## 交互状态

### 开场状态

纯黑背景显示开场文案。短暂停留后，文案和黑场收缩成一个点，点亮星空。开场只在首次进入或刷新时播放。

### 探索状态

全屏纯星空，无文字、无标签、无年份、无导航、无明显按钮。用户可以拖动画面在星海中漂移。拖动需要惯性和阻尼，不能像直接拖拽一张平面图片。

探索态允许较大拖动范围，但任何可到达区域都不能是空星海。如果某片区域还没有视觉内容，就不开放给用户拖过去。边界使用阻尼、暗流和回引效果处理，不做硬撞墙。

### 发现状态

用户靠近可点记录节点时，节点发光增强，周围星尘轻微聚集。拖动进入某片区域时，附近可点节点短暂显影。没有文字提示，所有反馈都通过光、雾、粒子完成。

### 阅读状态

用户点击节点后，星空背景保留但降噪处理，内容居中进入阅读模式。阅读态可以出现关闭或返回控制。控制优先使用图标或极简符号，不在探索态常驻。

阅读内容以自由 Markdown 为主。模板只用于辅助排版，不强制所有记录同构。

## 内容逻辑

内容本质是 Robin 的个人记录，不是知识库，也不是固定问答结构。

记录可以是：

- 思考感悟
- 个人价值观
- 项目经历
- 阶段复盘
- 灵感片段
- 作品说明
- 未来想法

首版使用纯测试占位节点验证前端体验，不急着填真实内容。

最低内容字段：

```text
title       标题，阅读态展示
date        日期，用于时间排布
type        类型，可选，用于后续辅助样式
summary     摘要，可选
importance 重要度，可选，影响节点亮度或大小
visibility 公开状态
body        Markdown 正文
```

字段只服务前端展示，不反过来限制内容表达。字段缺失时页面不能显示空模板或残缺占位。

## 技术路线

首版采用 2.5D 视差宇宙地图，不采用真 3D 大世界、Godot 主路线、360 全景运行时或 React/Next 重构。

推荐继续基于当前静态站推进，尽量不新增依赖。Three.js 可以保留在有价值的光效、粒子或星云层中，但整体交互按 2.5D 地图设计，限制相机自由度，避免进入真 3D 游戏工程。

推荐模块：

- `IntroController`：黑场开场、文案、收缩成点、星空亮起。
- `UniverseScene`：巨大星空画布、多层星云、星河、星尘、可拖动边界、视差漂移。
- `RecordNodeLayer`：记录节点位置、亮度、靠近显影、点击命中。
- `ReadingOverlay`：星空背景阅读模式、Markdown 渲染、关闭返回。
- `ContentLoader`：加载测试数据，后续接入真实 Markdown 记录。

## 非目标

- 不做传统首页、简历页、普通博客列表或营销 landing page。
- 不做完整游戏系统，不做角色、任务、背包、战斗、登录或存档。
- 不做 Godot Web 作为首版主技术路线。
- 不做 360 全景作为首版主运行时。
- 不做 React/Next 重构。
- 不在探索态显示年份、标签、导航、说明文字或明显按钮。
- 不为了展示内容密度硬塞大量假节点。

## 首版验收标准

- 打开后出现指定黑场开场文案。
- 开场收缩成点后，星空亮起。
- 探索态没有任何文字、年份、标签、导航和明显按钮。
- 用户可以在星海里上下左右自由拖动。
- 拖动时有明显但高级的视差漂移，不像拖一张平面图。
- 可到达区域不能是空白星海。
- 背景星点多，可点记录节点少。
- 可点节点能被自然发现：呼吸、靠近增强、拖动显影。
- 点击节点后进入星空背景阅读模式。
- 阅读内容可以显示 Markdown，占位内容即可。
- 关闭阅读后回到纯星空探索态。
- 桌面和移动端都能使用，移动端可以降低粒子和拖动范围，但不能退化成普通列表。
- 不新增复杂依赖，不做 Godot、Next 或 360 全景重构。

## 风险

视觉资产质量决定上限。代码可以保证层次、视差和动效，但无法只靠参数做出真正高级的宇宙画面。

视差漂移是核心体验，需要专项打磨。它不能被当成普通拖拽实现。

完全无 UI 会提升沉浸感，但也会增加可发现性风险。节点的亮度、靠近反馈和拖动显影必须足够明确。

## 后续实施建议

第一阶段先做最小前端闭环：开场、星空拖动、视差层、测试节点、阅读模式。

第二阶段再替换高质量星空资产，并细调水墨星云、光河和节点反馈。

第三阶段才接入真实 Markdown 内容，并根据真实记录调整时间分布和节点重要度。
