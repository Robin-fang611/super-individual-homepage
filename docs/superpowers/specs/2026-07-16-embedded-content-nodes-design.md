# 原场景嵌入式内容节点设计规格

**状态：** 已确认

**目标：** 在当前线上水墨宇宙场景、构图、色调和自由飞行体验完全不变的前提下，加入始终可见、克制且可点击的空间内容节点，并通过镜头推进进入现有阅读内容。

**基准版本：** `baseline/online-2026-07-15-ink-universe`，对应线上代码提交 `186f5eab1c370e489353923dd564f8fe1ec704b8`。任何升级失误都必须能够回到此基准。

## 1. 核心判断

这次升级不是重新设计场景，也不是为场景增加一套轨道、路线或菜单。当前3D场景是一张不可改动的母片；新节点只是嵌入既有空间坐标中的轻量交互物。

节点的存在需要让访问者一眼知道“这里可以点击”，但不能成为新的视觉主角。视觉优先级固定为：

1. 水墨宇宙和暴风眼；
2. 用户当前正在接近或悬停的节点；
3. 其余节点；
4. 文字说明。

## 2. 硬约束

- 不修改 `createInkUniverseWorld` 的世界构图、全景图、色彩分级、墨云、暴风眼、星屑数量或既有动画参数。
- 不增加轨道、连线、路径、星座、浮岛、建筑、HUD 面板或新的装饰性背景。
- 不新增或升级第三方依赖，继续使用原生 ES Modules、Three.js 本地模块、HTML 和 CSS。
- 节点数量与内容类型不在本阶段定死；首轮用现有公开记录验证视觉和交互，节点系统必须与具体文案解耦。
- 继续保持纯静态部署。
- 当前版本对鼠标和触控板桌面端负责；移动端只保证内容不溢出，不把移动端交互作为本阶段发布门槛。
- 保留 WebGL 失败回退、自动画质和原有自由飞行能力。

## 3. 节点视觉

### 3.1 默认状态

- 节点由一个冷白色核心光点、一圈极细的半透明外环和一个短标题组成。
- 核心视觉直径约 `6px`，但按钮的实际点击区域至少 `36px × 36px`。
- 外环视觉直径约 `18–22px`，线宽 `1px`，透明度约 `0.28`。
- 标题使用现有字体栈，视觉字号 `11–12px`，字重 `400`，透明度 `0.34–0.40`。
- 标题常显，不需要用户猜测节点是否可点击。
- 核心和外环以约 `4s` 为周期做一次幅度很小的呼吸；缩放范围不超过 `0.94–1.06`。
- 不使用高饱和紫色、荧光描边、扫描线、粒子爆发或持续旋转。

### 3.2 靠近与悬停状态

- 指针进入节点点击区域后，标题在 `220–280ms` 内视觉放大至 `15–16px`，透明度提高到 `0.92–1`。
- 通过 `transform: scale(...)` 完成视觉放大，避免改变排版尺寸导致文字跳动。
- 核心光点亮度轻微提高，外环扩大约 `10–14%`；不得照亮或重绘周围场景。
- 同一时刻最多一个节点进入强调状态。
- 键盘聚焦与鼠标悬停使用同一视觉反馈。

### 3.3 深度与遮挡

- 节点使用世界坐标锚定，再投影到屏幕，不随页面滚动或固定在视口角落。
- 相机转向后，位于相机背面、裁剪范围外或视口外的节点必须隐藏。
- 节点在屏幕上的视觉尺寸只做有限距离修正，保证可读性，不能像普通3D模型一样缩小到不可点击。
- 首轮采用手工标定的锚点，不用算法生成路线：

| 槽位 | 初始世界坐标 | 用途 |
|---|---|---|
| `vortex-primary` | `(1.55, 1.00, 2.20)` | 入场视野内的首要节点 |
| `vortex-secondary` | `(2.05, 0.42, 0.35)` | 稍深处的第二节点 |
| `vortex-tertiary` | `(1.10, -0.22, -1.40)` | 远处的第三节点 |

这些坐标只决定交互物的位置，不改变场景本身。实施阶段允许在固定验收截图中小幅标定坐标，但不能改变节点数量、结构或世界构图来迁就位置。

## 4. 点击与内容过渡

### 4.1 进入

完整进入过程控制在 `1.2–1.6s`：

1. 点击后 `0–180ms`：当前节点外环收紧，标题淡出，其余节点退场。
2. `180–1350ms`：相机沿当前视线向节点平滑推进，在节点前约 `1.35` 个世界单位停止。
3. `1150–1500ms`：现有阅读层从节点中心方向渐入；不使用白屏闪烁、硬切或传统弹窗弹跳。
4. 阅读层打开后，背景水墨宇宙仍可见，动画速度降至正常状态的 `0.18`，输入暂时锁定。

相机位置和朝向只能由 `UniverseRuntime` 写入，不能让节点组件直接修改相机，从而保持现有“单一 PlayerRig 真源”约束。

### 4.2 阅读状态

- 复用现有 Markdown 内容加载和 HTML 转义能力。
- 复用现有阅读层结构，但降低卡片感：扩大透明区域、弱化边框，让内容像从节点内部展开。
- 场景保持在阅读层后方，不跳转到独立页面。
- 阅读期间不响应飞行输入，避免正文阅读和背景移动相互干扰。

### 4.3 返回

- 点击关闭或按 `Escape` 后，阅读层先淡出。
- 相机用进入动画的反向路径返回点击前的精确位置和朝向。
- 返回过程结束后恢复节点、自由飞行输入和正常世界动画速度。
- 连续快速点击只接受第一次，直到进入或返回过程完成。

### 4.4 减少动态效果

当 `prefers-reduced-motion: reduce` 生效时：

- 不播放呼吸循环。
- 节点标题仍保留悬停放大和透明度变化，但时长缩短到 `80ms`。
- 点击后不执行长距离镜头推进，只做 `120–180ms` 交叉淡化并打开内容。
- 关闭内容同样直接恢复原位。

## 5. 内容与节点的关系

节点视觉不得依赖正文内容。数据流固定为：

```text
content/records/index.json
  → loadRecords()
  → mapRecordsToSpatialNodes(records, slots)
  → SpatialNodeLayer
  → 用户选择 node.recordId
  → ReadingOverlay.open(record)
```

- `record.id` 是节点和内容之间的唯一稳定关联键。
- 节点标题默认使用 `record.title`；未来可以新增独立短标题字段，但不属于本阶段。
- 公开记录多于槽位时只展示最前面的三个；少于槽位时只创建对应数量节点。
- 内容加载失败时不创建无内容节点，页面仍可自由探索。

## 6. 架构边界

### 新增模块

- `src/universe/spatial-node-layout.mjs`：把记录映射到固定世界坐标槽位；纯数据、可测试。
- `src/universe/spatial-node-layer.mjs`：创建可访问的 DOM 按钮，把世界坐标投影到屏幕，并管理 idle、hover、active 和 hidden 视觉状态。
- `src/universe/focus-transition.mjs`：纯函数计算镜头推进和返回的时间进度、位置与四元数插值。

### 修改模块

- `index.html`：在 canvas 之后增加节点层容器。
- `styles.css`：增加节点视觉、阅读层过渡和 reduced-motion 规则；不改世界背景规则。
- `src/app.mjs`：把 records、节点层容器和阅读层连接起来；删除读取时直接 `pause()` 的旧行为。
- `src/star-field.mjs`：组装节点层、投影更新、内容模式动画速率和焦点 API；不修改世界构造。
- `src/universe/runtime.mjs`：让 PlayerRig 独占镜头推进、内容锁定和返回状态。
- `src/universe/experience-state.mjs`：增加 `focusing → content → returning` 状态。
- `src/reading-overlay.mjs`：提供进入和退出完成通知，让镜头过渡与内容层时序一致。

### 不修改模块

- `src/universe/ink-world.mjs`
- `src/universe/ink-panorama.mjs`
- `src/universe/ink-color-grade.mjs`
- `src/universe/quality-profiles.mjs`
- 全部 `assets/images/ink-universe-panorama-*`

## 7. 状态流

```text
intro / handoff
  → active
  → focusing
  → content
  → returning
  → active

任意运行状态 → error
```

- `active`：飞行输入开启，节点可点击。
- `focusing`：输入锁定，节点退场，相机向目标推进。
- `content`：阅读层打开，背景低速运行。
- `returning`：阅读层关闭，相机返回保存姿态。
- 重复点击、非法关闭或非法返回均为 no-op。

## 8. 错误处理与清理

- 节点创建失败不得破坏 WebGL 场景；记录错误后继续运行无节点版本。
- 记录不存在或不可公开时不进入焦点动画。
- WebGL context lost 继续走现有 fallback 路径。
- `destroy()` 必须移除节点 DOM、事件监听、未完成动画和 Promise 回调。
- 相机过渡中发生异常时恢复点击前姿态、重新激活输入并保持阅读层关闭。
- 关闭阅读层后焦点必须回到触发节点按钮；节点已不存在时回到 canvas 容器。

## 9. 可访问性

- 每个节点必须是原生 `button`，可通过 Tab 和 Enter/Space 操作。
- 节点按钮的可访问名称使用记录标题。
- 节点层只承载交互，装饰光点和外环标记为 `aria-hidden="true"`。
- 阅读层继续使用 `role="dialog"`、`aria-modal="true"` 和 Escape 关闭。
- 透明度不能成为唯一状态提示；hover/focus 同时使用尺寸和光环变化。

## 10. 性能预算

- 节点层不新增网络请求、不新增纹理、不新增第三方脚本。
- 每帧最多投影三个节点，DOM 写入只在坐标、可见性或模式发生变化时执行。
- 节点系统不得改变当前画质档选择、全景图分辨率或 `inkWorld` 对象数量。
- 全部节点与过渡逻辑的新增未压缩 JavaScript 目标不超过 `18 KiB`。
- 运行十分钟不得持续增加 DOM 节点、事件监听或动画句柄。

## 11. 验收标准

### 自动验证

- `node --test tests/*.test.mjs` 全部通过。
- `node scripts/validate-content.mjs` 输出 `Validated 3 public star nodes.`。
- 新增测试覆盖：固定槽位映射、前后裁剪、投影坐标、单节点强调、非法状态转换、焦点进入与返回、reduced-motion、清理事件监听和缺失记录。
- 现有世界视觉测试必须继续证明 `ink-world.mjs` 没有路线、前景河或新粒子系统。

### 视觉验证

- 使用当前基准提交和升级提交，在同一桌面分辨率、同一画质档、同一初始机位分别截图。
- 屏蔽节点层后，两张截图的场景像素必须一致；差异只允许来自既有时间动画。
- 默认状态中节点清晰可发现，但第一眼视觉重心仍是暴风眼。
- 悬停时只有目标节点放大和增亮，周围场景不闪烁、不变色。
- 点击、内容阅读和返回形成连续动作，没有白屏、硬切、相机跳变或输入穿透。
- 关闭内容后相机位置与四元数恢复到点击前，容差分别为 `0.001` 和 `0.0001`。
