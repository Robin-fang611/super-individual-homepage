# Robin 个人宇宙地图实施计划（中文版）

## 目标

把当前个人主页第一阶段重做成一个可验证的前端闭环：

- 黑场开场。
- 星空亮起。
- 纯星空探索态。
- 上下左右自由拖动。
- 认真做 2.5D 视差漂移。
- 少量可发现记录节点。
- 点击节点后进入星空背景阅读模式。

首版只验证前端体验，不急着填真实内容。真实思考、价值观、项目经历后面再逐步替换进去。

## 核心技术判断

这次不走真 3D 大世界，也不走 Godot，不做 360 全景运行时，不重构成 React/Next。

第一版采用 **2.5D 视差宇宙地图**：

- 背景星云一层。
- 主星河一层。
- 近景星尘一层。
- 可点击记录节点一层。

用户拖动时，不同层用不同速度移动，形成“在宇宙里漂移”的感觉。这样比真 3D 稳，也更贴合你现在想要的自由探索感。

## 不做什么

- 不删旧文件。
- 不新增依赖。
- 不主动提交 git。
- 不做普通首页、简历页、博客列表。
- 不做角色、任务、背包、战斗、登录、存档。
- 不在探索态显示文字、年份、标签、导航、按钮。
- 不为了显得内容多而塞很多假节点。

## 文件怎么拆

计划会新增或修改这些文件：

- `index.html`  
  换成新的页面壳：开场层、星空画布、阅读层。

- `styles.css`  
  改成新视觉系统：黑场开场、全屏星空、阅读模式、隐藏式控制。

- `src/app.mjs`  
  做总入口：加载记录、启动开场、启动星空、打开/关闭阅读模式。

- `src/record-content.mjs`  
  读取和解析 Markdown 记录。

- `src/universe-layout.mjs`  
  负责星点、记录节点、视差、拖动边界、点击命中这些数学逻辑。

- `src/intro-controller.mjs`  
  负责黑场文案和“收缩成点、星空亮起”的开场状态。

- `src/universe-scene.mjs`  
  负责 Canvas 星空渲染、拖动、惯性、视差、节点显影。

- `src/reading-overlay.mjs`  
  负责点击节点后的星空背景阅读模式。

- `content/records/`  
  放首版测试记录。只是测试节点，不代表最终内容。

- `tests/*.test.mjs`  
  加测试，锁住内容解析、布局逻辑、开场状态和页面壳。

旧的 `src/star-field.mjs`、`src/star-layout.mjs`、`src/star-content.mjs` 第一阶段不删除，避免回滚困难。

## 任务拆分

### 任务 1：建立记录内容格式

先做 Markdown 记录的读取逻辑。

首版记录字段很少：

```text
title       标题，阅读态展示
date        日期，用来决定星体在时间星河里的位置
type        类型，可选
summary     摘要，可选
importance 重要度，可选，影响节点亮度或大小
visibility 公开状态
body        Markdown 正文
```

重点是：内容可以自由写，不强制每条记录都按同一个模板。

验收：

- 能解析 Markdown frontmatter。
- 能按日期排序。
- 字段缺失时不出现空模板。
- 首版有 3 条纯测试记录。

### 任务 2：建立宇宙布局数学

做这些底层逻辑：

- 生成大量背景星点。
- 按时间生成少量可点记录节点。
- 计算不同图层的视差位移。
- 限制用户拖动范围。
- 判断鼠标是否点中节点。

验收：

- 同一个 seed 生成的星点稳定。
- 新记录离用户更近，旧记录更远。
- 视差层移动速度不同。
- 拖动不会进入空白区域。

### 任务 3：替换页面壳和开场

把旧的星路页面壳替换成：

- `intro-screen`：黑场开场。
- `universe-canvas`：星空画布。
- `reading-overlay`：阅读模式。

开场文案固定为：

```text
这里是，我的世界
                               ——Robin
```

验收：

- 页面没有旧的 `STAR ROAD`、年份、导航、标签。
- 开场状态能按时间变化：黑场、文字、收缩、星空亮起、结束。

### 任务 4：实现阅读模式

点击记录节点后：

- 星空仍然作为背景。
- 背景变暗、变慢或轻微失焦。
- 内容居中显示。
- 支持标题、日期、摘要、Markdown 正文。
- 可以按关闭按钮或 `Esc` 返回星空。

验收：

- Markdown 能显示基本标题和段落。
- 阅读态可关闭。
- 关闭后回到纯星空探索。

### 任务 5：实现 Canvas 宇宙场景

这是最重要的一步。

要实现：

- 多层背景星点。
- 主星河光流。
- 少量记录节点。
- 鼠标/触控拖动。
- 惯性和阻尼。
- 多层视差漂移。
- 节点靠近时发光增强。
- 点击节点进入阅读模式。

验收：

- 拖动时不是平面图片移动。
- 远景、中景、近景有不同速度。
- 画面没有空白黑区。
- 可点节点能被自然发现。

### 任务 6：串起整个应用

在 `src/app.mjs` 里把所有模块串起来：

1. 加载测试记录。
2. 启动阅读层。
3. 启动宇宙场景。
4. 启动开场动画。
5. 点击节点时暂停星空，打开阅读。
6. 关闭阅读时恢复星空。

验收：

- `window.__universeBoot.step` 最终是 `ready`。
- 页面能完整从开场进入探索，再进入阅读，再返回探索。

### 任务 7：浏览器手动验收

桌面端检查：

- 黑场开场出现。
- 文案正确。
- 星空亮起。
- 探索态无文字、无标签、无导航。
- 可以上下左右拖动。
- 视差明显但不廉价。
- 点击节点能打开阅读模式。
- 关闭后回到星空。

移动端检查：

- 开场能完整显示。
- 触控拖动可用。
- 不退化成普通列表。
- 阅读层能在手机屏幕内滚动。

### 任务 8：完整验证

跑新测试：

```powershell
node --test tests/record-content.test.mjs tests/universe-layout.test.mjs tests/intro-controller.test.mjs tests/app-shell.test.mjs
```

再跑旧测试，确认没有意外破坏旧模块：

```powershell
node --test tests/star-content.test.mjs tests/star-layout.test.mjs tests/star-field-controls.test.mjs
```

最后检查 git diff：

```powershell
git status --short
git diff -- index.html styles.css src/app.mjs src/record-content.mjs src/universe-layout.mjs src/intro-controller.mjs src/reading-overlay.mjs src/universe-scene.mjs
```

验收标准：

- 只改计划中的文件。
- 没有无关文件混入。
- 没有新增依赖。
- 没有删除旧文件。

## 第一阶段完成后的效果

第一阶段完成后，网站应该能做到：

1. 打开是黑场和一句话。
2. 黑场收缩，星空亮起。
3. 用户进入纯星空，不看到网页 UI。
4. 用户可以在星海里自由拖动。
5. 拖动有认真做的视差漂移。
6. 少数可点节点能被发现。
7. 点击节点进入星空背景阅读。
8. 关闭后回到星空。

这时内容还可以是测试内容。只要前端体验成立，后面再换真实记录。

## 风险提醒

这个方案的上限主要取决于视觉资产和视差打磨。

代码可以做出层级、拖动、显影和阅读闭环，但如果星云、水墨、光河素材不够好，页面还是会显得普通。所以第一阶段先验证交互骨架，第二阶段再重点打磨宇宙视觉。

另一个风险是完全无 UI 会让用户不知道哪里能点。这个问题要靠节点呼吸、靠近发光、拖动显影来解决，不能靠文字提示。
